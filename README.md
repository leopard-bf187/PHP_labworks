## Задание 2. Использование готовых шаблонизаторов

На втором этапе был подключен шаблонизатор Twig с использованием Composer.

### Реализовано:
- установка Twig через Composer;
- создание отдельной директории templates_twig/;
- переписывание всех шаблонов с использованием синтаксиса Twig;
- использование механизма наследования шаблонов;
- передача данных из PHP в Twig через метод render().

### Пример инициализации Twig
```php
$loader = new FilesystemLoader(__DIR__ . '/../templates_twig');
$twig = new Environment($loader);
```

### Пример рендера шаблона
```php
echo $twig->render('list.twig', ['entries' => $entries]);
```

### Использование наследования
```php
{% extends "layout.twig" %}
```

## Контрольные вопросы

### 1. В чём отличие нативных PHP-шаблонов от шаблонизатора Twig? Какие преимущества и недостатки у каждого подхода?
Нативные PHP-шаблоны используют обычный PHP-код внутри файлов представления. Они просты и не требуют дополнительных библиотек, но при большом проекте код легко смешивается с логикой.
Twig использует отдельный шаблонный синтаксис и лучше подходит для разделения логики и интерфейса. Его плюс — более чистая структура, минус — необходимость установки и настройки.


### 2. Зачем разделять логику и представление в проекте? Какие проблемы могут возникнуть, если смешивать их в одном файле?
Разделение логики и представления делает код более понятным, удобным для поддержки и расширения.  
Если всё писать в одном файле, код становится запутанным, его сложнее изменять и искать ошибки.


### 3. Что такое наследование шаблонов в Twig? Как работают `{% extends %}` и `{% block %}`?
Наследование шаблонов позволяет использовать один общий шаблон для нескольких страниц.  
`{% extends %}` подключает базовый шаблон, а `{% block %}` задаёт части, которые можно переопределить в дочернем шаблоне.
